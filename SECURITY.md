# Security and safety reporting

For a vulnerability involving code execution, private data, or repository infrastructure, use GitHub private vulnerability reporting when enabled.

For harmful aviation guidance, calculation defects, stale safety-critical sources, or agent behavior that could be mistaken for operational authority, open an issue labeled `safety-critical` without including personal or aircraft-identifying data. State the scenario, observed output, authoritative source, and potential consequence.

Maintainers should acknowledge safety-critical reports within two business days, disable clearly harmful content promptly, and publish the correction and source trail.
